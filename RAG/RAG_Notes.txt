Text Splitter:
we are going to see 3 types of text splitting methods. 
1.Character - Based Splitting 
	Character-based splitting is the simplest method of text splitting.It divides a large document into smaller chunks based on the number of 	
characters, without understanding words, tokens, or meaning.
2.Token-Based Splitting
	Token-based splitting divides a document into chunks based on the number of tokens, not characters.Since LLMs process tokens instead of words, 
this 	method aligns better with how models actually read text.
3.Semantic / Meaning-Based Splitting
	Semantic / Meaning-Based Splitting divides a document into chunks based on the meaning and structure of the text, rather than characters or 
tokens.
	The goal is to keep complete ideas together so that each chunk contains a coherent piece of information.

Retrievers:A retriever takes a user query and returns the most relevant documents or chunks from a database.
Now there are 2 types of retriever 
	by data source (Wikipedia, Arxiv, PubMed, etc.)
	By retrieval strategy (Similarity, MMR, MultiQuery, etc.) 

by data source:
When we talk about retrievers using data sources, we mean retrievers that fetch information from specific external sources or databases instead of 
your 
own vector store. These retrievers connect to APIs or datasets and return relevant documents for the query.


By retrieval strategy:
In most RAG (Retrieval-Augmented Generation) systems, retrievers mainly use three core retrieval strategies. These are the ones you’ll see most often 
in real projects and tutorials.
	Similarity Search (Most Common)
		Cosine similarity (most common)
		Dot product
		Euclidean distance
		The retriever finds the most similar vectors.
		Top-K documents are retrieved

------------------------------------------------------------------------------------------------------
Data stored         Structured data (text, numbers, rows)       Embeddings (vectors like [0.23, -0.41, ...])

Runnables:
The issue was that each of them had their own SDK, their own syntax, and their own way of calling the model.Because of this, if you built your 
project using one provider, like OpenAI, and later decided to switch to something like Gemini or Claude, you basically had to rewrite a large part of 
your code. That was frustrating 
and time-consuming.

Langchain provides a unified interface that means no matter which llm you use ,way you write code almost remains same , just changes the model.
You have:
•some kind of input processing
•then a prompt template
•then the LLM call
•and then an output parser
At this point, you can clearly see that your application is no longer just a single model call.Now you have multiple components involved things like 
LLMs, prompt templates, output parsers, and even custom logic in between.And all of these components need to work together in a proper sequence to 
give you the final result.


They made our code cleaner, reduced repetition, and allowed us to connect multiple components into a single pipeline.So now if you look at this, even 
though we are using better components like prompt templates, models, and output parsers… we are still doing everything manually.
We have to:
•format the prompt
•call the model
•parse the output

While traditional LangChain runs in a straight line (Step 1 → Step 2 → Step 3 → Done), LangGraph allows your program to make decisions, loop back, 
re-try steps, and remember what happened earlier.
The 3 Core Pillars of LangGraph:
1. State (The Shared Memory)
2. Nodes (The Workers / Actions)
3. Edges (The Pathways & Decisions)


Graph DB:
A Graph DB in RAG (GraphRAG) solves this by extracting entities (people, places, concepts) and their explicit connections, allowing the LLM to follow 
relationships across multiple documents.
Lowers hallucination because connections are explicitly defined facts.Finds interconnected entities and traces multihop relationships.



Extraction (Ingestion): An LLM reads raw text and extracts structured facts into a Knowledge Graph.

Example Text: "Elon Musk leads Tesla, which manufactures the Cybertruck."     Graph Extracted: (Elon Musk) -[LEADS]-> (Tesla) -[MANUFACTURES]-> 
(Cybertruck)
Vector Search: To fetch relevant semantic text chunks.

Graph Search (Cypher/Graph Query): To fetch connected entities and multi-step relationships.

Hybrid Retrieval: When a user asks a question, the system queries both: Vector Search + Graph Search

An AI agent perceives user goals, autonomously decides which tools to execute in sequence, and performs multi-step real-world actions to solve a task.


A bot follows predefined, rule-based scripts to perform specific repetitive tasks, whereas an AI agent uses reasoning to autonomously plan, adapt, 
and execute multi-step actions using external tools to achieve dynamic goals.

It demonstrates the fundamental ReAct (Reasoning + Acting) loop: the LLM receives a prompt, decides to execute external functions (tools), parses the 
results, and loops until the final answer is generated.

The 4 Core Pillars of Agentic AI
Planning & Decomposition	Breaking a complex user goal into smaller, manageable sub-tasks.
Memory	        Retaining short-term working context and long-term historical knowledge.
Tool Use (Grounding)	Overcoming LLM limits (hallucination, knowledge cutoff, math limits) via external APIs.
Self-Reflection & Error Recovery	Evaluating whether a step succeeded and adjusting the plan if it failed.



Multi-Agent Collaboration: Multiple specialized agents (e.g., Researcher, Coder, Reviewer) work together, passing state and critiquing each other's outputs.


Agentic AI is the autonomous decision-making brain that reasons and plans to achieve goals, while an MCP server is the standardized plug-and-play connector (the USB port) that securely exposes tools, files, and data for the agent to use.
