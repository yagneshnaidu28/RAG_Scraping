problems and solutions way of explanation:
if we have some pdf files, excel files or someother files related to our company or some project through direct apps interface it might take long time to upload and make understand of llm, because if llm dont have access to files and we wanted to work with it llm will give many hallucinations .

through which we can extract data from pdf or files, convert data to embeddings , store those numerical vectors(embeddings).into some db vectordb(like chromadb,pinecone),ask llm for answer to our query or question.

RAG Pipeline structure:

File ----> Chunks ()--> Embeddings (Numbers) --> Vector DB (Store)--> LLM (Answer).




Development Plan:
	1.user uploads files
	2.system loads documents into document loaders (Convert raw files into document objects that can be processed.)
	3.Text Splitting (Chunking)[documents are usually too large for LLM context windows.So we split them into smaller chunks.]
	4.Embedding Generation(Each chunk is converted into a vector embedding.Embedding models transform text into numerical vectors)These vectors 	represent semantic meaning.
	5.Vector Database Storage:All embeddings are stored inside a vector database.(embeddings,original text chunks,metadata)
	6.query->query embedding->similarity search->The retriever selects the top-k relevant chunks.These chunks form the context.->Based on the context 	the LLM answers.




RAG: 4 main process     document loader->text splitter->database->retrievers

most of the embedding and language models have context window which cannot take infinite tokens at same time so we use chunks,Smaller chunks allow the system to retrieve only the most relevant piece of information instead of the whole document.Large documents would make the pipeline slower and expensive.
Text Splitter:
we are going to see 3 types of text splitting methods. 
1.Character - Based Splitting 
	Character-based splitting is the simplest method of text splitting.It divides a large document into smaller chunks based on the number of 	characters, without understanding words, tokens, or meaning.
2.Token-Based Splitting
	Token-based splitting divides a document into chunks based on the number of tokens, not characters.Since LLMs process tokens instead of words, this 	method aligns better with how models actually read text.
3.Semantic / Meaning-Based Splitting
	Semantic / Meaning-Based Splitting divides a document into chunks based on the meaning and structure of the text, rather than characters or tokens.
	The goal is to keep complete ideas together so that each chunk contains a coherent piece of information.

Retrievers:A retriever takes a user query and returns the most relevant documents or chunks from a database.
Now there are 2 types of retriever 
	by data source (Wikipedia, Arxiv, PubMed, etc.)
	By retrieval strategy (Similarity, MMR, MultiQuery, etc.) 

by data source:
When we talk about retrievers using data sources, we mean retrievers that fetch information from specific external sources or databases instead of your 
own vector store. These retrievers connect to APIs or datasets and return relevant documents for the query.


By retrieval strategy:
In most RAG (Retrieval-Augmented Generation) systems, retrievers mainly use three core retrieval strategies. These are the ones you’ll see most often in real projects and tutorials.
	Similarity Search (Most Common)
		Cosine similarity (most common)
		Dot product
		Euclidean distance
		The retriever finds the most similar vectors.
		Top-K documents are retrieved

	MMR (Max Marginal Relevance):
		Imagine you are building a RAG system for your students.Your knowledge base contains many chunks about Gradient Descent.Your database chunks 		look like this:
		Search Strategies - MMR (maximum marginal relevance)
		Chunk 1: Gradient descent is an optimization algorithm used in machine learning.
		Chunk 2: Gradient descent minimizes the loss function.
		Chunk 3: Gradient descent  is an optimization that minimizes the loss function.
		Chunk 4: Neural networks use gradient descent for training.
		Chunk 5: Support Vector Machines are supervised learning algorithms.
		
		Its goal is to balance two things:
			Relevance to the query
			Diversity among retrieved documents

	MultiQuery Retriever

		So Instead of using one query, it generates multiple variations of the query using  an LLM. so now the pipeline becomes 
			User Query->LLM generates multiple queries->Retriever searches for each query->Combine all retrieved documents







Feature             Normal Database                             Vector Database
------------------------------------------------------------------------------------------------------
Data stored         Structured data (text, numbers, rows)       Embeddings (vectors like [0.23, -0.41, ...])
Search type         Exact match                                 Similarity search
Query example       WHERE movie = "Interstellar"                "movies about space travel"
Indexing            B-Tree, Hash                                HNSW, IVF, PQ
Use case            Banking, user records, transactions         AI search, recommendations, RAG
Comparison method   Equality or filtering                       Cosine similarity / vector distance
